## What's Changed

- Customize portal messages, simplify key actions, and document Docker hierarchy by @brtydse100 in [#46](https://github.com/brtydse100/litegate/pull/46)
- fix: correct the nightly E2E Node action pin by @brtydse100 in [cf73f2d](https://github.com/brtydse100/litegate/commit/cf73f2d19d849ed11249ef3b21cc7b120e79264f)

### Independent login and My key messages

Set `login_text` to replace the login subtitle and `my_key_text` to display
guidance below the My key action area, before and after key creation. The
messages are independent, support line breaks, and display HTML and Markdown
literally. Empty login text keeps the existing subtitle; empty My key text
hides the guidance. The existing `logo_url` now also supplies the login logo.

Docker uses these settings in its mounted `config.yaml`; environment equivalents
are `LOGIN_TEXT`, `MY_KEY_TEXT`, and `LOGO_URL`. Helm uses `config.loginText`,
`config.myKeyText`, and `config.logoUrl`. Environment values override YAML.
Restart the backend or recreate the container after changes; Helm deployments
also need a restart after upgrading the appearance values. No frontend rebuild
is needed for runtime text or image URLs. Bundling a new image asset still
requires a build or an explicit static-file mount.

Both configuration endpoints are public. Keep the messages and logo appropriate
for unauthenticated visitors. No authentication, key policy, or secret-storage
defaults change. See the [configuration guide](../configuration.md#login-page-customization).

### One key action after creation and regeneration

For one-time secrets, **Hide API key** replaces the regeneration action below
the information card while the new secret is visible. Hiding the secret restores
the regeneration action, subject to the existing cooldown. Copying, stored-key
reveal behavior, confirmation, and spend-preserving rotation remain supported.

### Docker organization hierarchy documentation

The hierarchy guide now gives Docker/Compose YAML and JSON environment examples,
read-only file mounts, container paths, configuration precedence, and restart
instructions alongside Helm setup. It clarifies that spending allowances and
informational group totals are separate from RPM, TPM, and concurrency limits.
See [Docker and Compose hierarchy setup](../organization.md#docker-and-compose).

### Nightly E2E repair

The nightly workflow referenced a truncated, invalid `actions/setup-node` SHA,
so GitHub Actions stopped before installing dependencies or running tests.
It now uses the verified full SHA already used by CI. The nightly schedule,
Node version, browser suite, and permissions are unchanged.
