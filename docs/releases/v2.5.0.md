# LiteGate 2.5.0

LiteGate 2.5 makes the self-service portal safer to operate, easier to validate,
and more reliable during LiteLLM or identity-provider failures.

## Highlights

- Portal sessions now use HttpOnly cookies with origin checks instead of
  browser-readable storage, and OIDC login verifies browser-bound state and
  nonce values.
- Users keep accumulated key spend when regenerating a credential.
- Administrators can search and select every matching key while the ordinary
  user dashboard remains lightweight.
- Request IDs, structured secret-free logs, authenticated Prometheus metrics,
  readiness checks, and verified SQLite backup/restore improve operations.
- Public HTTP contracts, browser workflows, dependency audits, Helm lint, and
  a non-root container build run in CI.

## Upgrade

```bash
docker pull ghcr.io/brtydse100/litegate:2.5.0
```

The image continues to run as UID/GID `10001:10001`. Existing volumes already
migrated for 2.4 need no additional storage change.

New sessions use `JWT_SECRET`. To rotate it without immediately signing users
out, temporarily put the former value in `JWT_PREVIOUS_SECRETS` until one full
session lifetime has elapsed.

See the [deployment guide](../../DEPLOYMENT.md) for backup, restore, Docker and
Helm instructions.
