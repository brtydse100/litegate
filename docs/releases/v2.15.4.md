# LiteGate v2.15.4

## Highlights

- **Saved keys:** Preserve original identifiers when refreshed metadata contains null/masked/replaced IDs; wait for configuration/key lookup before suggesting replacement. Ownership checks are unchanged; this reproduces an overwrite bug, not the cause of a specific deployed incident.
- **Startup:** Await the first hierarchy reconciliation attempt, then retry every 60 seconds. Exact IDs take precedence; email discovery scans pages for one exact normalized match and rereads its actual ID.
- **Safety:** Skip missing users; discovery creates/deletes/rotates no users or keys. Existing migration retains secrets, aliases, models and spend.

## Upgrade Notes

- Preserve SQLite and the same owner for stored secrets; no new dependencies, services, tables or settings.
- Remote email assignments are operator policy, not SSO proof. Revalidate every pass; ambiguous/incomplete/changed results, local/admin matches and path conflicts skip writes with errors. Existing verified claims, subject login and secret ownership rules remain.
- Scans allow 100 pages of 100 users, 60 seconds and five concurrent lookups. Per-user failures retry; startup completion does not guarantee every remote write succeeded. Helm allows 30 minutes for startup; larger installs may need longer.
