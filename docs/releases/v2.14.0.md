## What's Changed

- docs: highlight Helm upgrade in v2.13.0 release notes by @brtydse100 in [#31](https://github.com/brtydse100/litegate/pull/31)
- Show individual member usage in leaf organization groups by @brtydse100 in [#32](https://github.com/brtydse100/litegate/pull/32)
- Prepare v2.14.0 with automatic key migration and stable rotation names by @brtydse100 in [#33](https://github.com/brtydse100/litegate/pull/33)

### Key migration and presentation

- Existing owned keys move in place into the primary mapped/default SSO team or
  deepest configured organization team, including keys previously in other
  teams. Secrets and spend remain intact. Old memberships and their spend
  records are retained for administrator review.
- Managed keys retain verified inherited allowances and ancestor-restriction
  safeguards. Failed migrations can be retried and are bounded to 500 existing
  keys per user. Existing policy-verification failures still require attention.
- Personal spend uses six decimal places. Rotated keys use the normal
  `name's key` name; replacement temporarily frees a conflicting alias while
  keeping the old credential live until generation succeeds.
- Saved-key reveal behavior is unchanged.

### Upgrade

Upgrade the Helm chart and application image together. Preserve the existing
SQLite volume and key-storage setting to retain saved secrets. Review team
mappings before rollout: login and reconciliation now move keys already assigned
to another team into the configured team without requiring manual migration.
