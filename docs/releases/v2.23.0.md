# LiteGate v2.23.0

## Highlights

- **No duplicate teams after a restructure:** When a group moves to a new place
  in the hierarchy, LiteGate reuses the existing LiteLLM team with the same name
  instead of creating a second one. It reuses only an unambiguous match and
  audits why when it cannot.
- **Cleanup that finishes the job:** With `organization_cleanup_enabled`, people
  who moved leave their old teams, and removed teams that LiteGate created or
  reused are deleted once empty.
- **Faster admin pages for large organizations:** Key search, the Organization
  page and the background sync make far fewer LiteLLM requests, and a budget
  change no longer makes sign-ins read the whole installation.
- **Smoother loading:** Loading placeholders, admin pages that load on first
  visit, no reload when you return to the tab, and paged local accounts.

## Upgrade Notes

- **`organization_cleanup_enabled` now deletes teams.** It previously only
  audited removed teams. It stays off by default; review it before upgrading if
  you turned it on. Teams LiteGate did not create or reuse, and teams named in
  other settings, are never changed.
- A key or member added directly in LiteLLM to a removed team just before its
  deletion is removed with the team.
- A renamed group still gets a new team; set `litellmTeamId` to keep one.
- One automatic SQLite migration adds the team-reuse table. No new settings or
  dependencies.
