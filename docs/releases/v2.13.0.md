# LiteGate v2.13.0

## Highlights

- **Hierarchy:** Up to eight configured levels, real LiteLLM teams and deepest-group key assignment. Inherited `perUser` means a per-key allowance; ancestor `groupTotal` values track spend and do not block requests.
- **Policies:** Editors show saved values/models and submit changed fields only; managed teams are tagged and controls follow the theme.
- **Key safety:** Verify ownership/allowances before removing duplicate personal/member/obsolete shared caps. Unknown credentials retain caps; conflicting or policy-losing migrations fail with warnings. Explicit unmanaged sole-key migration keeps shared team caps.
- **Rotation:** Preserve spend, known finite budgets and reset intervals under the owner lock; revoke unverifiable replacements before deleting originals.
- **Portal/testing:** Unified copy/show/hide controls, sub-cent spend and isolated LiteLLM/OpenRouter helpers with artificial local accounting rates, separate from provider cost.

## Upgrade Notes

- Hierarchy defaults off (`organizationHierarchy.levels: []`). Back up SQLite and LiteLLM policies before enabling; upgrade chart and image together.
- LiteLLM requires a database and key/team APIs. Daily analytics depend on version/license; reports attribute history using current membership. Native team spend stays with the owning team.
- Secret storage stays off by default; authorized revealed secrets remain in component memory. Provider test credentials are entered locally.
