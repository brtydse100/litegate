# LiteGate 2.3.0

LiteGate 2.3.0 adds safe, administrator-controlled member moves between
LiteLLM teams.

## Highlights

- Open a team's **Members** dialog and choose **Move** beside a user.
- Search for and select a destination team, acknowledge the budget and access
  policy change, then move the user and their scoped keys in a few clicks.
- Keep the member's existing LiteLLM team role at the destination.
- Use the equivalent administrator-only
  `POST /api/v1/teams/{source_team_id}/members/move` route for automation.

## Safety and access

Normal users cannot open team management or call the move endpoint. A trusted
agent may use LiteGate's installation-wide `management_api_key`, which has
administrator access and must be protected like a password.

Removing a LiteLLM team member also deletes that member's keys scoped to the
team. LiteGate therefore performs a move in this order: add the destination
membership, reassign and verify source-team keys, then remove the source
membership. A failed key migration keeps the source membership. Each operation
is limited to 500 source-team keys, and configuration-managed source teams are
blocked until `oidc_group_team_mapping` or `KEY_TEAM_ID` is changed.

## Upgrade

Pull `ghcr.io/brtydse100/litegate:2.3.0`, update the Helm chart, or rebuild from
source. No LiteGate database migration or new configuration value is required.
The connected LiteLLM deployment must provide team member add/delete,
paginated team listing, key listing, and bulk key update management routes.
