# LiteGate 2.1.0

LiteGate 2.1 maps identity-provider groups to existing LiteLLM teams so team
budgets and model policy can follow users at sign-in.

## What changed

- Added case-insensitive SSO group-to-team mapping with flat or dotted claim
  paths.
- One SSO group can map to one or several LiteLLM team IDs.
- Sign-in additively creates missing memberships without deleting manually
  managed memberships.
- An optional fail-closed setting rejects SSO users who match no configured team.
- The first matched team becomes the primary team for newly created or
  regenerated keys.

## Configuration

```yaml
oidc_groups_claim: "groups"
oidc_group_team_mapping:
  Engineering: "team-engineering"
  AI-Platform:
    - "team-platform"
    - "team-shared-services"
oidc_require_team_mapping: false
```

Mapping values are LiteLLM team IDs, not aliases, and each team must already
exist. Environment-based deployments can provide the equivalent JSON through
`OIDC_GROUP_TEAM_MAPPING`.

## Important behavior

A LiteLLM virtual key has one team ID. If several mappings match, LiteGate adds
all memberships but assigns the first configured match to new keys. Existing
keys are not changed automatically. Regenerate them or update their `team_id` as
an administrator.

```bash
docker pull ghcr.io/brtydse100/litegate:2.1.0
```

See [SSO team mapping](../authentication.md#mapping-sso-groups-to-litellm-teams).
