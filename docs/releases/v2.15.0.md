# LiteGate v2.15.0

## Highlights

- **Email mapping (historical):** Inline/file named levels and parent inheritance supplement SSO groups; original flat mappings remain supported, with existing SSO/hierarchy budget precedence.
- **Provisioning:** Keyless ordinary users and additive memberships; SQLite bindings connect authenticated subjects later. Unproven email matches remain pending, superseded reservations are retained, and removing configuration does not revoke memberships.
- **Delivery:** Require verified PR preview images; stable publication remains on validated main.

## Upgrade Notes

- **Upgrade to [v2.15.1](https://github.com/brtydse100/litegate/releases/tag/v2.15.1) for hierarchy email assignments.** This version rejects mapped emails with `email_verified: false` even when `generic_require_verified_email` / Helm `config.genericRequireVerifiedEmail` is disabled.
- v2.15.1 removes `organization_mapping`, `organization_mapping_file`, Helm `config.organizationMapping` / `config.organizationMappingFile`. Move emails to `organizationHierarchy` members' `userIds` alongside `ssoGroups` before upgrading.
- Upgrade chart/image together and preserve SQLite; identity tables initialize automatically. Referenced teams must exist. Use one inline/file source; restart after JSON changes (inline Helm changes roll out automatically).
- Review pending identities and retained users in LiteLLM, including user-count impact. No user deletions or key transfers occur.
