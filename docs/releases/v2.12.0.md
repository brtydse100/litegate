## What's Changed

- Added generic OAuth SSO with authorization, token, and authenticated UserInfo
  endpoints, including opaque access tokens and configurable user ID/email
  fields, by @brtydse100 in [#18](https://github.com/brtydse100/litegate/pull/18).
- Added root-level Compose YAML and Helm `config:` settings with optional
  LiteLLM-style `GENERIC_*` environment overrides, scopes, S256 PKCE, and body or
  OAuth-compliant HTTP Basic client authentication.
- Kept browser-bound signed state, HttpOnly sessions, existing administrator and
  team rules, and verified OIDC mode. Generic UserInfo role fields do not grant
  administrator access; incomplete or conflicting provider settings fail startup.
- Added backend and Helm regressions, including credential encoding and
  portable Helm rendering checks. The independent implementation judge scored
  the final change 4/4, and all six PR CI jobs passed, including the container
  build and live LiteLLM integration.
- Standardized historical release notes and documented this format in
  `AGENTS.md` for future releases.

### Upgrade notes

No database migration is required from 2.11.0. Existing OIDC and local-account
configuration remains compatible. To enable generic SSO, leave the OIDC issuer
and manual endpoints blank, set both generic client credentials and all three
generic endpoints, and register `/api/auth/callback` with the provider. The
callback defaults to `root_url` plus that path; `generic_redirect_uri` overrides
it when the backend uses a different public origin.

Use a stable UserInfo identity field matching your existing LiteLLM user IDs.
LiteGate defaults to `sub`; changing the field or OAuth client can produce
separate user records. Microsoft Entra UserInfo omits groups/custom claims;
use OIDC mode when group mapping relies on verified ID-token claims. The
generic mode covers the documented OAuth options, not LiteLLM custom handlers,
static state, custom headers, token-claim merging, or role mappings.

See the [authentication guide](../authentication.md#generic-oauth-sso),
[configuration reference](../configuration.md#generic-oauth-sso), and
[Helm deployment guide](../../DEPLOYMENT.md#generic-oauth-sso-in-helm).
