# LiteGate 2.4.0

LiteGate 2.4 closes a key-rotation budget bypass, prevents repeated mutation
clicks during cooldowns, and runs the packaged application without root.

## What changed

- Regenerated keys inherit accumulated spend, so secret rotation does not reset
  their per-key allowance.
- Key, account, team, and bulk-edit controls are disabled during the server-side
  operation cooldown and show the remaining wait time.
- The all-in-one image runs as UID/GID `10001:10001` with Nginx on unprivileged
  container port `8080`.
- The Helm chart enables non-root execution, drops Linux capabilities, prevents
  privilege escalation, applies runtime-default seccomp, and configures storage
  ownership through `fsGroup`.

## Upgrade

```bash
docker pull ghcr.io/brtydse100/litegate:2.4.0
```

New volumes need no preparation. Volumes first created by LiteGate 2.3 or older
may be owned by root. From `deploy/docker-compose`, migrate one once:

```bash
docker compose -f docker-compose.image.yml run --rm --user 0 \
  --entrypoint chown litegate -R 10001:10001 /app/backend/data
docker compose -f docker-compose.image.yml up -d
```

Kubernetes persistent volumes use the chart's `fsGroup: 10001` default.

## Budget behavior

LiteGate preserves key-level spend during self-service regeneration. Use
LiteLLM user or team budgets when you need a cumulative ceiling shared across
multiple credentials or keys created outside LiteGate.

See the [deployment guide](../../DEPLOYMENT.md) for Docker and Helm details.
