## What's Changed

LiteGate 2.6 refreshes the self-service experience, makes the public demo fully
interactive, and expands automated quality checks without changing the
deployment architecture or configuration contract.

- A responsive LiteLLM-inspired interface gives users clearer key, budget,
  model, expiry, team, and rate-limit summaries while administrators retain the
  complete key, user, team, and status workflows.
- A persisted light/dark theme is available from both the sign-in screen and
  the authenticated portal.
- The public demo now runs the real frontend against synthetic browser-local
  data and can switch between administrator and ordinary-user views.
- Pull requests run lint, format, type, unit, backend coverage, focused browser,
  dependency, documentation, Helm, container, and real LiteLLM compatibility
  checks; the complete browser suite runs nightly.
- A disposable integration stack pins LiteLLM and PostgreSQL images by digest
  and exercises live user, team, and virtual-key operations through the service
  and browser API layers.
- Live compatibility fixes prevent LiteLLM from creating an unrevealed key
  during user provisioning and normalize nested team-update responses.
- Refreshed screenshots, SVGs, and video provide sharper documentation with
  smaller downloads.

### Upgrade

No configuration or storage migration is required from 2.5.0. The container
continues to run as UID/GID `10001:10001`, and production installations should
continue pinning the image rather than using `latest`.

See the [deployment guide](../../DEPLOYMENT.md) for Docker Compose, Helm,
backup, and upgrade instructions.
